# 工况结构、参数化轨迹与运动设备监测设计

## 1. 目标与范围

本次改造解决三个相关问题：

1. 工况管理中的“新建”对象应是场景组、场景子组、场景三种结构节点，而不是 AEB、RCTA、LKA 等业务类型。
2. 轨迹不再依赖逐点录入或地图拖拽，改为通过连续的直线段和恒半径圆弧段建立，并自动计算运动参数。
3. 底部状态监测保留两个监测位，但允许操作员从所有支持运动遥测的设备中选择，并查看通用运动数据。

地图始终只读。本次不实现地图增删、拖拽航点，不实现缓和曲线、道路网络和任意样条曲线。

## 2. 三层工况结构

### 2.1 数据模型

新增通用目录节点，节点类型固定为：

- `Group`：场景组，只能位于根节点下。
- `Subgroup`：场景子组，只能位于场景组下。
- `Scenario`：具体场景，只能位于场景子组下。

每个节点包含稳定 ID、父节点 ID、名称、节点类型和显示顺序。AEB、RCTA、LKA、目标类型及 NCAP 标准版本属于具体场景的业务属性，不作为目录节点类型。

目录清单与具体场景参数分开持久化。目录清单保证空场景组和空场景子组可以保存；具体场景继续使用 JSON 参数文件。程序启动时合并内置场景与用户目录，兼容现有 `scenarios/*.json`。

### 2.2 创建入口

工况列表面板上方设置一个“＋”按钮，移除底部“新建工况”按钮。点击“＋”后选择：

- 新建场景组：只输入组名称。
- 新建场景子组：输入名称并选择父场景组。
- 新建场景：输入名称并选择父场景组、父场景子组。

三层节点均支持右键新建，采用层级感知菜单：

- 右键场景组：新建子组或场景。新建场景时锁定场景组并要求选择其子组。
- 右键场景子组：新建场景并锁定组与子组。
- 右键场景：新建同级场景，锁定相同组与子组。

同一父节点下名称不可重复，名称去除首尾空白后不能为空。创建成功后刷新目录，展开父节点并选中新节点。所有创建结果在重启后保留。

### 2.3 组件边界

`ScenarioCatalog` 负责节点关系、创建校验、排序与持久化。QML 不直接修改目录数据，只调用控制器接口并响应目录变更信号。现有树形视觉结构保留，只增加顶部工具栏和各层右键菜单。

## 3. 参数化轨迹编辑

### 3.1 轨迹模型

主车和目标平台分别维护一条轨迹。每条轨迹由有序的 `TrajectorySegment` 组成，段类型为：

- `Straight`：直线段。
- `CircularArc`：恒半径圆弧段。

第一段允许编辑起点 X、Y 和起始速度。后续段的起点与起始速度由上一段终点和末速度继承，界面只读，从而保证位置与速度连续。

每段均包含终点 X、Y、末速度。直线段派生长度和航向角。圆弧段额外包含转弯半径与左/右转方向，默认使用小圆弧，并派生圆心、圆心角和弧长。

### 3.2 编辑联动

- 修改直线段终点坐标时，反算段长与航向角。
- 修改直线段航向角时，保持段长并绕段起点旋转终点。
- 圆弧段由起终点、半径和转向求解；半径必须不小于弦长的一半。
- 修改前段后，下一段起点自动更新；后续段保持原长度和相对方向并整体传播，保证轨迹不断裂。
- 修改一段末速度时，下一段起始速度同步更新。
- 整条轨迹提供旋转角度控制，绕第一段起点旋转所有段，保持长度、半径和速度不变。
- 支持新增直线段、新增圆弧段、复制、删除、上移和下移。

地图只显示计算后的轨迹、段序号、起终点和方向，不响应轨迹编辑手势。

### 3.3 运动计算

界面速度单位为 km/h，计算和持久化统一为 m/s。对于路径长度 `s`、起始速度 `v0` 和末速度 `v1`：

- 平均切向加速度：`a = (v1² - v0²) / (2s)`。
- 当 `v0 + v1 > 0` 时，预计时长：`t = 2s / (v0 + v1)`。
- 圆弧最大横向加速度：`a_lat = max(v0, v1)² / r`。

长度为零、速度为负、非零长度但两端速度均为零、圆弧半径小于弦长一半或几何求解失败时，轨迹无效。界面定位到错误段并禁止保存。

### 3.4 执行与预览的一致性

`TrajectoryGeometry` 是纯计算模块，负责校验、派生参数、整轨旋转和采样点生成。参数化轨迹是持久化源数据；保存时由该模块生成执行引擎使用的采样点。只读地图与执行引擎使用同一份采样结果，避免预览和实际运动不一致。

## 4. 可选运动设备状态监测

### 4.1 设备能力与遥测

设备配置增加“支持运动遥测”能力标记。底部设备选择器只展示具备该能力的设备，不依赖设备名称，也不把可选范围硬编码为驾驶机器人和目标平台。

通用 `DeviceStatus` 和 `DeviceListModel` 增加：

- X 位置，单位 m。
- Y 位置，单位 m。
- 速度，内部单位 m/s，界面显示 km/h。
- 航向角，界面规范化为 `0–360°`。

运动遥测由具体设备实现更新，并通过设备列表模型统一暴露。状态监测不再直接读取 `StateManager` 中固定的主车和目标物字段。

### 4.2 双监测位交互

底部保留两个并排监测卡，每张卡顶部有设备选择器。两张卡不能选择同一设备；切换时自动保持不同选择。

每张卡显示设备名、在线/心跳、X、Y、速度、航向角、延迟、丢包率和信号强度。离线设备仍可选择，但实时值显示“—”；恢复连接后自动刷新。

两个监测位的选择保存在本机。应用重启后恢复；已选设备被移除时，回退到第一个未被另一监测位占用的可用运动设备。

## 5. 数据流与错误处理

### 5.1 工况目录

QML 创建动作 → `AppController` → `ScenarioCatalog` 校验并持久化 → 发出目录变更信号 → QML 刷新、展开并选择新节点。

写入失败时不修改内存目录，界面保留对话框并显示可操作错误。加载时遇到损坏的用户目录，不影响内置场景加载；错误记录到报警系统并忽略损坏条目。

### 5.2 轨迹

轨迹段表单 → `TrajectoryGeometry` 实时校验与派生 → 采样结果更新只读地图 → 保存参数化轨迹与采样点 → `ScenarioEngine` 加载同一采样结果。

无效字段以段级错误呈现。保存失败时保留编辑内容，不覆盖上一次有效版本。

### 5.3 设备状态

设备遥测 → `DeviceManager` → `DeviceListModel` 通用角色 → 两张监测卡按所选设备索引显示。设备列表变更时重新校验两个选择，避免越界和重复。

## 6. 测试与验收

### 6.1 自动测试

- 目录：三种节点创建、父级约束、同级重名、空节点持久化、重载恢复、现有 JSON 导入。
- 几何：直线派生、圆弧左右转、非法半径、角度旋转、连续段传播、速度连续、单位换算、加速度和时长。
- 设备：运动能力过滤、两个槽位去重、选择恢复、设备移除回退、离线占位和遥测角色刷新。
- 回归：现有配置解析、场景执行、航点模拟、设备状态和数据库测试继续通过。

### 6.2 界面验收

- 工况列表顶部显示“＋”，底部不再显示新建按钮。
- 顶部“＋”和三层右键菜单均能按规则创建节点，重启后节点仍存在。
- 直线和圆弧可连续拼接，地图只读且与参数编辑实时同步。
- 输入示例起点 `(0,0)`、起速 `0 km/h`、终点 `(100,0)`、末速 `10 km/h` 时，系统自动显示距离、方向、平均加速度和预计时长。
- 调整整轨角度后，所有段绕首个起点旋转且轨迹连续。
- 两张底部卡可从运动设备中选择不同设备，并实时显示 X、Y、速度、航向角和通信状态。
- 完整构建、QML 静态检查和桌面应用目标交互均通过，无相关运行时警告。
